and the migrated implementation using the same frozen historical Demand input:

```text
data/processed/fifth_ring/order_pipeline/orders_region_assigned.csv.gz
```

```text
outputs/refactor-validation/phase5b-supply/legacy-historical-demand/
```

The existing `data/processed/fifth_ring/supply/` directory was read only.

## Exact three-way result

The legacy rerun, migrated rerun, and historical formal Supply products are
identical under chunked contract validation. The validator streamed all rows,
checked schema, integer dtype, non-negativity, primary-key uniqueness and
ordering, time/cluster axes, summary consistency, and complete row hashes.

## Baseline interpretation

This validates Supply migration independently of the Demand cross-platform
gate: both implementations read the same historical Demand file. It also shows
that the current Linux execution exactly reproduces the historical formal
Supply aggregates despite the historical Demand products having been generated
on Windows. No Supply historical reproduction gate is required.

The optional secondary comparison using the Linux Demand validation baseline
was not run because the primary old/new comparison and historical three-way
comparison are already exact. It would test a different Demand input and is not
needed to establish Supply migration equivalence.
